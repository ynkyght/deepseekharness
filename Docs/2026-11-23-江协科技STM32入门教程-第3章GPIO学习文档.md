## 0. 一句话说清这一章

把**引脚**从「芯片上的金属脚」变成「可编程资源」：先用 `GPIO_Init` 把某个引脚配成 8 种模式中的一种，之后就能用两三个库函数读电平 / 写电平 / 整端口写。本章 5 个例程 = 同一条初始化骨架的 5 次复用，**真正要背下来的只有那一套骨架**。

## 1. 你昨天看到的「位」是哪个「位」

第 3 章里有三个容易混的「位」，互不相同：

| 名字 | 在哪 | 讲什么 | 学完要能回答 |
|---|---|---|---|
| **GPIO 位结构** | 课件 slide 20（一张图） | 一个引脚内部的电路：保护二极管 → 上/下拉电阻 → 施密特触发器 → 输入数据寄存器；输出侧 P-MOS/N-MOS → 输出控制 | 为什么上拉输入悬空是高电平？为什么开漏输出「高电平是高阻」？ |
| **位操作** | 工程 3-1 代码（三种写法） | 只改端口 16 位里的某一位，别动其它位 | `GPIO_SetBits/ResetBits/WriteBit` 分别写哪个寄存器？为什么比读改写 ODR 安全？ |
| **优先级里的「位」** | 第 5 章 slide 45 | NVIC 4 位优先级切成抢占位 + 响应位 | 本章不涉及，看到先跳过 |

> 你停在 slide 20 的话，那就是第一节 **GPIO 位结构**——它是「8 种模式为什么长这样」的答案，值得花 20 分钟对着图把信号走向走一遍。

### 1.1 位结构图的信号走向（按 RM0008 §9.1.1 的顺序读）

```
引脚 ──┬─ 保护二极管(上:接VDD / 下:接VSS) ── 5V 容忍引脚没有上面那只
       │
       ├─ 上拉电阻(~40kΩ) ─┐
       ├─ 下拉电阻(~40kΩ) ─┤→ 开关由 CRL/CRH 的 CNF/MODE 控制
       │
       ├─(输入方向) 施密特触发器 → 输入数据寄存器 IDR（读这个就是读引脚电平）
       │
       └─(输出方向) 输出控制 ← 输出数据寄存器 ODR / 复用功能输出
                     ↓
                P-MOS(接VDD) + N-MOS(接VSS) → 推到引脚
```

- **推挽输出**：P-MOS 和 N-MOS 都用，高电平真的接 VDD、低电平真的接 VSS，能拉能灌。
- **开漏输出**：只用 N-MOS，高电平=「关断」，引脚靠外部上拉才有高电平；这也是 I2C 必须开漏的原因（第 4 章 OLED 的 SCL/SDA 就是 `GPIO_Mode_Out_OD`）。
- **输入模式**：输出级的 MOS 全关，信号经施密特触发器进 IDR；选上拉/下拉只是决定悬空时的默认电平。
- **模拟输入**：施密特触发器也被旁路，引脚直连 ADC，所以 ADC 通道必须配 `GPIO_Mode_AIN`（第 7 章会用）。

## 2. 8 种模式：一张表记住

课件 slide 21 给了特征表，这里加上**库枚举名**和**你在教程哪一章会用到**（枚举值与 `stm32f10x_gpio.h` 原文一致）：

| 模式（中文） | 库枚举 | GPIO 配置值 | 性质 | 一句话判据 | 本章/后续用处 |
|---|---|---|---|---|---|
| 模拟输入 | `GPIO_Mode_AIN` | 0x0 | 模拟 | 引脚直连 ADC，GPIO 功能关闭 | 第 7 章 AD |
| 浮空输入 | `GPIO_Mode_IN_FLOATING` | 0x04 | 数字输入 | 悬空时电平不确定 | 外部已有上/下拉时用 |
| 下拉输入 | `GPIO_Mode_IPD` | 0x28 | 数字输入 | 悬空默认低 | 高电平有效的按键 |
| 上拉输入 | `GPIO_Mode_IPU` | 0x48 | 数字输入 | 悬空默认高 | 3-4 按键、3-5 光敏、第 5 章 EXTI |
| 开漏输出 | `GPIO_Mode_Out_OD` | 0x14 | 数字输出 | 高电平=高阻，低电平接 VSS | 4-1 OLED 软件 I2C |
| 推挽输出 | `GPIO_Mode_Out_PP` | 0x10 | 数字输出 | 高接 VDD、低接 VSS | 3-1/3-2 LED、3-3/3-5 蜂鸣器 |
| 复用开漏 | `GPIO_Mode_AF_OD` | 0x1C | 数字输出 | 输出由片上外设控制，高阻/低 | 10-2 硬件 I2C |
| 复用推挽 | `GPIO_Mode_AF_PP` | 0x18 | 数字输出 | 输出由片上外设控制 | 6-x PWM、9-x 串口 TX、11-2 硬件 SPI |

另外两个只管输出、不影响功能的参数：

- **输出速度** `GPIO_Speed_10MHz / 2MHz / 50MHz`（输出模式下才有效）；速度越高边沿越陡、功耗与 EMI 越大，**够用就好**，本章全用 50MHz 只是因为教程统一。
- **上/下拉电阻约 30–50 kΩ**（RM0008），只能提供弱默认电平，不能当驱动用；按键/光敏这类「要么悬空要么短路到地」的信号正合适。

> **5V 容忍**：数据手册标 FT 的引脚可承受 5V 输入，`PB0/PB1` 等模拟输入脚不是；接 5V 模块前查 `参考文档/` 里的引脚定义表（课件 slide 11 也有一张）。

## 3. 寄存器与库函数：写电平到底动了哪一位

| 寄存器 | 作用 | 关键特性 |
|---|---|---|
| `CRL`（配置引脚 0–7）/ `CRH`（8–15） | 每个脚 4 位：CNF[1:0] + MODE[1:0] | `GPIO_Init` 最终写这里 |
| `IDR` | 输入数据，只读 | `GPIO_ReadInputDataBit` 读它 |
| `ODR` | 输出数据，16 位 | `GPIO_Write` 整端口写；读它=读「我设的电平」而非引脚实际电平 |
| `BSRR` | 置位/复位寄存器 | **写 1 有效**：低 16 位置 1、高 16 位清 0；一次写，天然原子 |
| `BRR` | 复位寄存器 | 写 1 清 0（BSRR 高 16 位的等价物，老代码用它） |
| `LCKR` | 配置锁定 | 防止误改，本章不用 |

标准库函数实现（`Library/stm32f10x_gpio.c` 原文，决定了「为什么安全」）：

| 库函数 | 实际动作 | 备注 |
|---|---|---|
| `GPIO_SetBits(GPIOx, pin)` | `GPIOx->BSRR = pin` | 只置位，单次写，不读回 |
| `GPIO_ResetBits(GPIOx, pin)` | `GPIOx->BRR = pin` | 只清位 |
| `GPIO_WriteBit(GPIOx, pin, Bit_SET/RESET)` | 写 `BSRR` 或 `BRR` | 也是原子写（旧版库里才用读改写 ODR） |
| `GPIO_Write(GPIOx, portVal)` | `GPIOx->ODR = portVal` | **整个 16 位端口**一起写，3-2 流水灯靠它 |
| `GPIO_ReadInputDataBit` | 读 `IDR` 对应位 | 读的是引脚真实电平 |
| `GPIO_ReadOutputDataBit` | 读 `ODR` 对应位 | 读的是「你上次设的值」，LED 翻转用它最省事 |
| `GPIO_Init` | 按结构体算 CNF/MODE，写 `CRL`/`CRH` | 引脚号跨 7/8 边界也能一次配好 |

> **为什么强调原子性**：读 `ODR`→改一位→写回 `ODR` 之间若进中断，且中断里也改同一个端口，改动会丢。`BSRR/BRR` 是「写 1 才生效」的单次写，不会踩这个坑——这就是 `GPIO_SetBits/ResetBits/WriteBit` 都走 BSRR/BRR 的原因。

## 4. 初始化四步骨架（5 个例程都是它）

```c
/* 1. 开时钟：用哪个 GPIO 端口就开哪个 */
RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);

/* 2. 填结构体（3 个字段：模式、引脚、速度） */
GPIO_InitTypeDef GPIO_InitStructure;
GPIO_InitStructure.GPIO_Mode  = GPIO_Mode_Out_PP;      // 8 种模式之一
GPIO_InitStructure.GPIO_Pin   = GPIO_Pin_0;             // 可 | 多个：GPIO_Pin_1 | GPIO_Pin_2 / GPIO_Pin_All
GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;       // 仅输出模式有意义

/* 3. 交给库函数写寄存器 */
GPIO_Init(GPIOA, &GPIO_InitStructure);

/* 4. 设默认电平：先给「安全态」，再进主循环 */
GPIO_SetBits(GPIOA, GPIO_Pin_0);                        // 高=LED 灭（教程接法）
```

- **时钟**：`GPIOA`～`GPIOE` 与 `AFIO` 都在 **APB2** 总线上（`RCC_APB2PeriphClockCmd`），不像 TIM2 在 APB1；开错总线是最常见的「配了没反应」。
- **结构体成员顺序无所谓**，但漏填 `GPIO_Speed` 会是 0（未定义速度），编译器不报错；`GPIO_InitTypeDef` 没有默认值。
- **`GPIO_Pin_All` = 0xFFFF**，会把该端口 16 个脚全配置——3-2 故意这么干，代价见 §6 第 2 条。

## 5. 五个例程逐个拆

### 5.1 3-1 LED 闪烁：把「写一位」的三种写法都试一遍

- **接线**：LED 阳极经限流电阻接 **PA0**，阴极接 GND（`1-1 接线图/3-1 LED闪烁.jpg`；源码 `GPIO_Pin_0`）。
- **代码**（`3-1 LED闪烁/User/main.c`）：推挽输出 PA0，主循环里三种写法各跑一轮，每轮 500 ms 翻转：
  1. `GPIO_ResetBits/GPIO_SetBits` → 写 BRR/BSRR；
  2. `GPIO_WriteBit(..., Bit_RESET/Bit_SET)` → 写 BSRR/BRR；
  3. `GPIO_WriteBit(..., (BitAction)0/1)` → 同一函数，强制类型转换，证明 `BitAction` 就是枚举 0/1。
- **现象**：LED 每 500 ms 亮灭一次（三种写法现象完全一样）。
- **要记住的**：写一位有 3 个入口，底层都是 BSRR/BRR；`GPIO_Write` 是「整端口」另一个层次。

### 5.2 3-2 LED 流水灯：整端口写 + 取反的取巧

- **接线**：8 个 LED 阳极分别接 **PA0–PA7**，阴极共 GND（`1-1 接线图/3-2 LED流水灯.jpg` 可见 8 颗 LED 一排）。
- **代码**：`GPIO_Pin_All` 把 PA0–PA15 全配成推挽输出；主循环里 `GPIO_Write(GPIOA, ~0x0001)` → `~0x0002` → … → `~0x0080`，每步 100 ms。
- **为什么取反**：教程接法是「低电平点亮」，要让 PA0 亮就写 0、其余写 1；`~0x0001 = 0xFFFE`，正好 PA0=0、其余=1。**不取反就变成「只亮一颗、其余全亮」的反相流水**。
- **代价**：`GPIO_Pin_All` 也把 PA13/PA14（SWD 调试脚）配成了推挽输出。下载后调试器可能连不上（芯片复位后才恢复），**自己写代码时用 `GPIO_Pin_0 | ... | GPIO_Pin_7` 明确列出**。

### 5.3 3-3 蜂鸣器：低电平鸣叫 + 有源/无源

- **接线**：蜂鸣器模块信号脚接 **PB12**（`3-3 蜂鸣器/User/main.c`），模块自带驱动三极管，GPIO 只给电平。
- **代码**：PB12 推挽输出；`GPIO_ResetBits` → 响 100 ms，`GPIO_SetBits` → 停 100 ms，响两短声后停 700 ms。**有源蜂鸣器低电平触发**，写高才是「停」。
- **有源 vs 无源**（课件 slide 26）：有源内部自带振荡源，给直流就响、频率固定；无源要外部给方波，本章 GPIO 只能「抖动」出方波，**真正可控的是第 6 章 PWM**。

### 5.4 3-4 按键控制 LED：本章唯一的「输入 + 输出」闭环

- **接线**：两个 LED 接 **PA1、PA2**；两个按键接 **PB1、PB11**（另一脚接 GND，按下=低电平）。源码：`Hardware/LED.c`、`Hardware/Key.c`。
- **代码结构**：`LED_Init()` 配 PA1/PA2 推挽输出并先置高（灭）；`Key_Init()` 配 PB1/PB11 **上拉输入**（`GPIO_Mode_IPU`，悬空=高=未按下）；主循环 `KeyNum = Key_GetNum()`，为 1 翻 LED1、为 2 翻 LED2。
- **`Key_GetNum` 的消抖**（`Hardware/Key.c`）：读到低 → `Delay_ms(20)` 再确认 → `while (读到低);` 等松手 → 再 `Delay_ms(20)` 消抖 → 返回键码。
- **翻转用 `GPIO_ReadOutputDataBit`**：读 ODR 而不是 IDR，因为这里问的是「我上次让它输出什么」，不是引脚实际电平。
- **两个已知缺陷**：① 阻塞式——按住不放，`while` 会卡住整个主循环（教程注释明说）；② 20 ms 延时消抖会丢快按。非阻塞消抖要等第 6 章定时器。

### 5.5 3-5 光敏传感器控制蜂鸣器：数字量输入的最小用例

- **接线**：光敏模块 DO 接 **PB13**，蜂鸣器 **PB12**（源码 `Hardware/LightSensor.c`、`Buzzer.c`）。
- **代码**：`LightSensor_Init()` 把 PB13 配成上拉输入；`LightSensor_Get()` 直接 `return GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_13);`；主循环 `if (Get()==1) Buzzer_ON(); else Buzzer_OFF();`。
- **模块原理**（课件 slide 30）：光敏电阻与定值电阻分压 → 电压比较器 → 数字输出（DO）；模块上的电位器调阈值，**所以「怎么算暗」不是代码决定的，是电位器决定的**。
- **注意**：工程里同时带了 `Key.c/LED.c`，但 `main.c` 没调 `Key_Init/LED_Init`——**目录里有文件 ≠ 会被初始化**，判冲突看 `main.c`。

### 5.6 顺手要读的 Delay 模块（`System/Delay.c`）

```c
void Delay_us(uint32_t xus) {
    SysTick->LOAD = 72 * xus;      // 72MHz 内核时钟，1us 数 72 个
    SysTick->VAL  = 0x00;
    SysTick->CTRL = 0x00000005;    // bit2 CLKSOURCE=HCLK | bit0 ENABLE
    while (!(SysTick->CTRL & 0x00010000));   // bit16 COUNTFLAG 等计数到 0
    SysTick->CTRL = 0x00000004;    // bit0=0 关定时器（CLKSOURCE 保留）
}
```

- **不用配 SysTick**：内核自带的 24 位递减计数器，写 `LOAD` 就能用；`Delay_ms` 就是循环 1000 次 `Delay_us(1000)`。
- **上限**：`LOAD` 只有 24 位，72 MHz 下最大约 233 ms（源码注释写 `0~233015`，是 us 上限）——这就是为什么 `Delay_ms` 必须拆成多次 `Delay_us`。
- **两个坑**：① `72*xus` 写死 72 MHz，换板/换主频就失真（本机 F407/H743 工程别直接搬）；② SysTick 若被别的代码（RTOS、HAL 的 `HAL_Delay`）占用，会互相打架。

## 6. 本章的坑清单（现象 → 根因 → 修法）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 配完引脚毫无反应、读回永远不变 | 忘了 `RCC_APB2PeriphClockCmd`，寄存器写不进去 | 每个 `XXX_Init` 第一行先开时钟 |
| 2 | 下载后 Keil 连不上芯片 / 调试器报错 | `GPIO_Pin_All` 把 PA13/PA14（SWD）配成普通输出 | 只配用到的脚；已锁死时按住复位下载或 BOOT0 拉高进 ISP |
| 3 | 按键不按也乱跳、光敏读数乱变 | 配成浮空输入，悬空电平不确定 | 按键/光敏一律 `GPIO_Mode_IPU`（按下拉低） |
| 4 | 按住按键程序「死机」 | `Key_GetNum` 里 `while(按下);` 是阻塞等待 | 明白它阻塞即可；要求实时就改中断/定时器扫描 |
| 5 | 按一下翻好几次 | 机械抖动 + 没消抖（或消抖时间太短） | 20 ms 延时消抖（教程做法）；更稳用状态机 |
| 6 | LED 常亮或按反相逻辑亮 | 教程是**低电平点亮**，写高=灭；自己接的高电平点亮则相反 | 先确认 LED 极性/限流电阻接法，再定 `SetBits` 含义 |
| 7 | 蜂鸣器一直响或不响 | 有源模块低电平触发；无源模块给直流不响 | 有源按教程接；无源留给第 6 章 PWM 驱动 |
| 8 | 光敏怎么遮都一个状态 | 模块电位器阈值拧到头，或接到了 AO 脚 | 调电位器；确认接的是 DO 不是 AO |
| 9 | PB3/PB4/PA15 怎么配都没输出 | 复位后默认是 JTAG 引脚 | `GPIO_PinRemapConfig(GPIO_Remap_SWJ_JTAGDisable, ENABLE)`（只关 JTAG、保留 SWD） |
| 10 | 换个板子 Delay 快/慢几十倍 | `Delay_us` 里 `72*xus` 写死 72 MHz | 按实际主频改系数，或改用定时器/SysTick 中断计时 |
| 11 | 第 7 章 ADC 读数乱跳 | ADC 通道配成了上拉/浮空输入 | ADC 脚必须 `GPIO_Mode_AIN` |
| 12 | 只想改一个脚，结果整排都变了 | `GPIO_Write` 写的是整个 ODR | 改一位用 `SetBits/ResetBits/WriteBit` |

## 8. 和本机已有工程的衔接

本机的 F407/H743 EtherCAT 工程是 **HAL + CubeMX**，标准库代码不能直接粘；概念和骨架可以对照着记：

| 标准库（本章） | HAL（F407/H743 工程） |
|---|---|
| `RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE)` | `__HAL_RCC_GPIOA_CLK_ENABLE()` |
| `GPIO_InitTypeDef` + `GPIO_Mode_Out_PP` | `GPIO_InitTypeDef` + `GPIO_MODE_OUTPUT_PP`（另需 `Pull`、`Alternate` 字段） |
| `GPIO_Init(GPIOA, &s)` | `HAL_GPIO_Init(GPIOA, &s)` |
| `GPIO_SetBits / GPIO_ResetBits` | `HAL_GPIO_WritePin(GPIOA, GPIO_PIN_0, GPIO_PIN_SET/RESET)` |
| 无对应（自己读 ODR 再取反） | `HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_0)` |
| `GPIO_ReadInputDataBit` | `HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_0)` |
| `GPIO_Mode_AF_PP` | `GPIO_MODE_AF_PP` + `Alternate = GPIO_AFx_TIMx` |

> 两套库**不能同时链接**（同名 `GPIO_Init` 冲突）；学完本章回 F407 工程时，只搬「先开时钟、再填结构体、最后 Init」的顺序，不要搬函数名。

### 8.1 不用面包板的 5 分钟验证

手边只有 F103 核心板（模块资料编号 1）时，用板载 LED（**PC13**，低电平点亮）验证同一套骨架：

```c
RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOC, ENABLE);
GPIO_InitTypeDef s;
s.GPIO_Mode = GPIO_Mode_Out_PP;
s.GPIO_Pin  = GPIO_Pin_13;
s.GPIO_Speed = GPIO_Speed_2MHz;   // PC13 驱动能力弱，2MHz 足够
GPIO_Init(GPIOC, &s);
while (1) { GPIO_ResetBits(GPIOC, GPIO_Pin_13); Delay_ms(500);
           GPIO_SetBits(GPIOC, GPIO_Pin_13);   Delay_ms(500); }
```
