# F4 与 H7 的 FSMC/FMC 差异与两个通用坑

> 来源：F407 项目 project_memory.md（2026-11-04）、安富莱 STM32-V7 裸机例程 project_memory.md（2026-11-04）
> 整理时间：2026-11-04
> 结论已由两处 project_memory 的条目交叉核对；未在本机实板复验，标「待板端确认」

## 一句话结论

同一个外设，两家叫法不同、坑也不同：F4 叫 **FSMC**（只支持 NOR/PSRAM/NAND），H7 叫 **FMC**（多了 SDRAM）；
两者**地址注释都可能过时**，一律以代码里的宏为准。

## 对照表

| 项 | STM32F407（F4） | STM32H743（H7） |
|---|---|---|
| 控制器名 | FSMC | FMC |
| 典型用途 | DM9000 以太网（Bank3/NE3） | 74HC574 扩展 IO（FMC 总线） |
| 地址窗口 | 寄存器口 `0x68400000`、数据口 `0x68480000` | 实际 `0x60001000`（`bsp_fmc_io.c:62`） |
| 地址选择 | 两地址差 `0x80000` = bit19 → **A18 翻转** | 注释写 `0x68200000`/`0x64001000`，是 **V6 遗留**，与代码不符 |
| 关键陷阱 | ETH DMA 描述符不能放 CCM | 注释地址不可信；SDRAM 段要 UNINIT + zero_init |
| 来源 | F407 project_memory §二、§四 | V7 project_memory §2、§3 |

## 三个通用坑

1. **地址以代码为准，别信注释**
   - V7：`bsp_fmc_io.c:62` 的 `HC574_PORT` 是 `0x60001000`，头文件注释却写 `0x68200000`（V6 板遗留）。
   - F4：寄存器口/数据口只差一位（A18），改板时只看 A18 是否分离，别去动高位。
   - 适用边界：注释与代码冲突时，一律以参与编译的宏/指针为准；注释要当"历史线索"。

2. **链接脚本与工程选项会互相打架**
   - V7：工程勾了 Use Memory Layout from Target Dialog（`umfTarg=1`）时，改 `.sct` 完全不生效（现象：改了变量地址却没变）。
   - 排查顺序：先看 `uvprojx` 的 `umfTarg`，再判断该改 `.sct` 还是改对话框。

3. **外置 RAM/总线设备的段属性**
   - V7：SDRAM 段没加 UNINIT/zero_init，C 启动代码在 FMC 初始化前清零它 → 一用就 HardFault。
   - F4：DMA 描述符放在 CCM 里收包异常（CCM 不经 DMA 总线）。
   - 通用判据：**DMA 访问的缓冲区不要放 CCM/TCM；外置存储的段要显式 UNINIT**。

## 编码坑（与芯片无关，但同源）

安富莱例程源码是 **GBK**，F407 的 Docs 是 UTF-8。同一仓库混编时：
- 读源码用 GBK 解码，读文档用 UTF-8，不要一刀切
- F407 仓库因此把 `.gitattributes` 写成 `* -text`（禁止 git 做任何换行/编码转换）
