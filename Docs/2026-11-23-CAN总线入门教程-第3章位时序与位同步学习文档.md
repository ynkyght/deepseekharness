## 0. 一句话说清这一章

CAN 没有时钟线，收发双方只靠「每一位多长时间」这一个约定来对齐。**位时序**就是把一位切成 4 段（每段若干 Tq），让接收方知道「采样点在哪」；**硬同步 + 再同步**则让采样点在时钟有误差时还能被拉回位的中间。学完这一章要能回答：采样点为什么放在 75–87.5%、`SJW` 到底在补偿什么、例程的 48/2/3/2 为什么是 125 kbps。

## 1. 为什么需要位时序（PPT 19–20）

- CAN 只有 CAN_H / CAN_L 一对差分线，**没有时钟线**，所有节点靠「约定波特率」各自计时。
- 发送方按约定位时长，每隔固定时间输出一位；接收方按同样位时长去采样。
- 理想情况：接收方的采样点正好落在每一位的中心附近。
- 现实里两个误差源：
  1. **起点不对齐**：接收方不知道报文什么时候开始，采样相位随机；
  2. **时钟漂移**：两边晶振有误差（还有收发器延时、总线传播延时），误差随位数累积，采样点越走越偏，最后一位可能采到跳变沿上。

> 所以位时序要解决两件事：**（a）帧一开始就把相位对齐**（硬同步）；**（b）之后每个跳变沿都能小步修正**（再同步）。

## 2. 一位由四段组成（PPT 21）

协议把一位细分成 4 段，每段由若干个最小时间单位 **Tq** 构成：

| 段 | 英文 | 协议范围 | 作用 | 什么时候会变 |
|---|---|---|---|---|
| 同步段 | SS（Sync Segment） | 固定 **1 Tq** | 数据位跳变沿「应该」出现在这里 | 硬同步把整段位时间拨到它 |
| 传播段 | PTS（Propagation Time Segment） | **1–8 Tq** | 补偿收发器 + 总线上的物理传播延时（一个来回） | 配置时定死 |
| 相位缓冲段 1 | PBS1 | **1–8 Tq** | 再同步时可以被**加长**，把采样点往后推 | 再同步（有上限） |
| 相位缓冲段 2 | PBS2 | **2–8 Tq** | 再同步时可以被**缩短**，把采样点往前拉 | 再同步（有上限） |

```
一位 = SS(1) + PTS(1~8) + PBS1(1~8) + PBS2(2~8)   [单位 Tq]
              ↑                    ↑
          跳变沿应落这里        采样点 = SS+PTS+PBS1 之后
```

- **采样点** = 一位中「SS + PTS + PBS1」这一段结束的位置。
- **PBS2 是留给再同步的后手**：只要采样点之后还有余量，边沿晚到时就能靠缩短 PBS2 把采样点往前挪，而不用改整位长度。
- **Tq 本身能选多细？** Tq = 一个分频后的时钟周期，位速率越高，一位里的 Tq 越少（例程 125 kbps 一位 6 Tq，1 Mbps 时常见一位 8–18 Tq）。

## 3. 硬同步：只在帧第一个下降沿做一次（PPT 22）

- 每个节点内部都有一个「位时序计数器」。
- 收到 **SOF 的下降沿**时，接收方把自己的位时序计数器**拨到 SS 段起点**，与发送方对齐。
- **只在帧的第一个下降沿有效**，一帧只做一次。
- 硬同步后若双方时钟完全一致，后续每位采样点都会对齐；不一致就靠再同步。

> 记住这个「一次性」：硬同步解决起点，再同步解决漂移。两个机制不能互相替代。

## 4. 再同步：每个跳变沿都能微调（PPT 23）

时钟误差会让数据位边沿逐渐偏离 SS 段。规则是：

| 边沿实际位置 | 说明 | 本地时钟 | 调整动作 | 效果 |
|---|---|---|---|---|
| **早于** SS | 对端比本地快 | 本地偏慢 | **加长 PBS1**（最多加 SJW） | 采样点后移 |
| **晚于** SS | 对端比本地慢 | 本地偏快 | **缩短 PBS2**（最多减 SJW） | 采样点前移 |
| 正好落在 SS 内 | 没有相位误差 | — | 不调整 | — |

- **SJW（SJW，再同步补偿宽度）** = 单次再同步允许调整的最大 Tq 数，协议 **1–4 Tq**。
- 再同步发生在第一个下降沿之后的**每个数据位跳变沿**，每次调整量不超过 SJW。
- 这就是为什么采样点不能贴着位末尾：要留出 PBS2 让「拉回」有余量。

## 5. 波特率与采样点的公式（PPT 24）

```
一位时长 = (SS + PTS + PBS1 + PBS2) × Tq
波特率   = 1 / 一位时长
采样点   = (SS + PTS + PBS1) / (SS + PTS + PBS1 + PBS2)
```

课件例子：SS=1Tq、PTS=3Tq、PBS1=3Tq、PBS2=3Tq、Tq=0.5 us →

```
一位 = (1+3+3+3) × 0.5us = 5 us  →  波特率 = 1/5us = 200 kbps
采样点 = (1+3+3)/10 = 70%
```

## 6. 落到 STM32 bxCAN：四段怎么映射（PPT 48）

STM32 的 bxCAN 不让你单独填 PTS，而是把 PTS 并进了 BS1：

| 协议段 | bxCAN 里对应 | 范围 | 库字段 |
|---|---|---|---|
| SS | 固定 1 Tq | — | 无（隐含） |
| PTS | **并入 BS1** | — | 无独立字段 |
| PBS1 | BS1 的一部分 | BS1 = **1–16 Tq** | `CAN_BS1` |
| PBS2 | BS2 | BS2 = **1–8 Tq**（协议要求 ≥2） | `CAN_BS2` |
| SJW | SJW | **1–4 Tq** | `CAN_SJW` |
| Tq | 时钟分频 | — | `CAN_Prescaler`（= BRP[9:0]+1） |

于是 STM32 上的两个公式变成（APB1 = 36 MHz，F103 @72 MHz）：

```
Tq     = CAN_Prescaler / 36MHz
波特率  = 36MHz / CAN_Prescaler / (1 + BS1 + BS2)
采样点  = (1 + BS1) / (1 + BS1 + BS2)
```

### 6.1 最容易踩的「差 1」

库宏名里的数字是 **Tq 数**，但宏值比它小 1（因为寄存器字段 TS1/TS2 = Tq 数 − 1）：

```c
CAN_BS1_2tq = 0x01   /* TS1 写入 1 → BS1 = 2 Tq */
CAN_BS2_3tq = 0x02   /* TS2 写入 2 → BS2 = 3 Tq */
CAN_SJW_2tq = 0x01
```

所以 `CAN_BS1 = CAN_BS1_2tq` 表示「BS1 是 2 个 Tq」，**不是 1 个**。自己算公式时用「tq 数」；只有直接写 BTR 寄存器时才用「tq 数 − 1」。

### 6.2 例程 01 的四行到底配出了什么

`01-CAN总线单个设备环回测试/Hardware/MyCAN.c`：

```c
CAN_InitStructure.CAN_Prescaler = 48;          // 波特率 = 36M / 48 / (1 + 2 + 3) = 125K
CAN_InitStructure.CAN_BS1 = CAN_BS1_2tq;       // BS1 = 2 Tq
CAN_InitStructure.CAN_BS2 = CAN_BS2_3tq;       // BS2 = 3 Tq
CAN_InitStructure.CAN_SJW = CAN_SJW_2tq;       // SJW = 2 Tq
```

验算：

```
Tq    = 48 / 36MHz = 1.333 us
一位   = (1+2+3) × 1.333us = 8 us
波特率 = 1/8us = 125 kbps  ✔
采样点 = (1+2)/6 = 50%     ← 这就是问题所在（见 §7）
```

### 6.3 常用波特率的一组可用参数（36 MHz，计算值）

| 目标波特率 | Prescaler | BS1 | BS2 | SJW | 实际 | 采样点 |
|---|---|---|---|---|---|---|
| 125 kbps | 18 | 13 Tq | 2 Tq | 2 Tq | 125.000 k | 87.5% |
| 250 kbps | 18 | 6 Tq | 1 Tq | 1 Tq | 250.000 k | 87.5% |
| 500 kbps | 9 | 6 Tq | 1 Tq | 1 Tq | 500.000 k | 87.5% |
| 1 Mbps | 4 | 6 Tq | 2 Tq | 1 Tq | 1.000 M | 77.8% |
| 1 Mbps（备选） | 2 | 15 Tq | 2 Tq | 2 Tq | 1.000 M | 88.9% |

> **为什么 1 Mbps 拿不到精确 87.5%**：87.5% 要求一位 = 8 Tq（7/8），而 36 MHz / (BRP×8) = 1 Mbps 需要 BRP = 4.5，不是整数。所以只能取 77.8%（整数分频）或 88.9%（BRP=2，Tq 只 55.6 ns，对时钟抖动更敏感）。
> 以上均为**计算值**，上板前用 USB-CAN 分析仪或示波器核一次实际波特率与采样点。

## 7. 为什么 50% 采样点不能上真实总线

- 采样点放在一位的正中间（50%），意味着采样点之后只剩一半位时间给 PBS2 做再同步；一旦对端时钟略快/略慢、或总线延时偏大，边沿逼近采样点，就会**偶发位错误 → TEC 上涨 → 被动错误 / 总线关闭**。
- 业界惯例（CiA 与多数厂商推荐）：**采样点 75%–87.5%**；位速率越高，传播延时占比越大，采样点相应前移（1 Mbps 常取 75–80%）。
- 教程用 50% 是**教学妥协**：面包板短线 + 3 个节点 + 125 kbps，边沿质量好，能跑通；照抄到长线、多节点、加终端电阻、换收发器的现场就不一定。

**选采样点的经验规则**（工程做法）：

1. 先定位速率与采样点目标（125k/250k/500k 取 87.5%，1M 取 75–80%）；
2. 一位的 Tq 数尽量取 8–16（太少了 SJW 没余量，太多了分频频率高、对抖动敏感）；
3. SJW 取 1–2 Tq（且不超过 BS1/BS2）；
4. 用公式反算 BRP，确认是整数且实际波特率误差 < 0.5%；
5. 所有节点用**同一组**参数（采样点不一致本身就是互操作问题）。

## 8. 自己配一遍：从目标波特率倒推（可直接抄）

目标 250 kbps、采样点 87.5%、APB1 = 36 MHz：

```
设一位 = 8 Tq → 采样点 = 7/8 = 87.5%  → BS1 = 6 Tq、BS2 = 1 Tq
Tq = 1/250k/8 = 0.5 us  → Prescaler = 0.5us × 36MHz = 18
验算：36M / 18 / 8 = 250.000 kbps  ✔
```

```c
CAN_InitTypeDef s;
s.CAN_Mode      = CAN_Mode_Normal;      // 上真实总线（教程是 LoopBack）
s.CAN_Prescaler = 18;                   // 0.5 us / Tq
s.CAN_BS1       = CAN_BS1_6tq;          // 6 Tq
s.CAN_BS2       = CAN_BS2_1tq;          // 1 Tq（STM32 允许；协议 PBS2 最小 2 Tq，严格合规见本节末尾 16 Tq 方案）
s.CAN_SJW       = CAN_SJW_1tq;
s.CAN_NART      = DISABLE;              // 0 = 失败自动重传；单节点调试时注意会一直重发
s.CAN_TXFP      = DISABLE;
s.CAN_RFLM      = DISABLE;
s.CAN_AWUM      = DISABLE;
s.CAN_TTCM      = DISABLE;
s.CAN_ABOM      = ENABLE;               // 现场设备建议开：bus-off 自动恢复
CAN_Init(CAN1, &s);
```

> 若坚持「BS2 ≥ 2 Tq」（严格按协议），250 kbps 可改用 一位 = 16 Tq：BS1 = 13、BS2 = 2、Prescaler = 9 → 36M/9/16 = 250k，采样点 14/16 = 87.5%。

## 9. 怎么验证位时序配对了

| 手段 | 能看到什么 | 注意 |
|---|---|---|
| USB-CAN 分析仪（ZCANPRO / CANFDNET-200U） | 实际波特率、采样点（部分工具可读）、错误计数 | 分析仪内部可能自带 120 Ω，接上后变成 60 Ω（见知识库整理稿 §5.1） |
| 示波器/逻辑分析仪抓 CAN_TX | 一位的宽度、Tq 个数（回环模式下 TX 引脚也有波形） | 抓的是 MCU 侧数字波形，不是总线差分 |
| 两节点互发 + 读 TEC/REC | 参数不匹配时会看到 TEC/REC 上升、错误帧 | 最贴近现场 |
| 回环模式 | **只能验证外设与软件流程** | 自己收自己，收发同一时钟，**波特率写错也能通**，所以验证不了位时序 |

## 10. 坑清单（现象 → 根因 → 修法）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 波特率差整数倍（如实际 62.5k 而非 125k） | 拿 72 MHz 算 APB1（实际 36 MHz）；或系统时钟没到 72 MHz（HSI 8 MHz 下同一配置只有 27.8 kbps） | 用 `RCC_GetClocksFreq()` 读实际 PCLK1 再算，别写死 |
| 2 | 按公式算对了、实测却差一位 | 把库宏值当 tq 数（`CAN_BS1_2tq`=0x01 是 2 Tq，不是 1 Tq） | §6.1：算公式用 tq 数，写寄存器才减 1 |
| 3 | 两个节点都「能发」但互收不到、TEC 涨 | 两边采样点/波特率不一致（一边 50% 一边 87.5%） | 全网统一参数；用分析仪核 |
| 4 | 短线上正常、线一长就错误帧 | 采样点太靠中间 + 没终端电阻 + 传播延时吃掉余量 | 采样点调到 75–87.5%；总线两端各 120 Ω |
| 5 | SJW 设 4 也救不回来 | SJW 只能修单次误差，且不能超过 BS1/BS2 的余量 | SJW 取 1–2 Tq，重点在采样点与终端电阻 |
| 6 | 回环模式一切正常，接上总线就挂 | 回环模式验证不了位时序（自己收自己） | 用两节点或分析仪验证 |
| 7 | 改 PB8/PB9 后完全不通 | 不是位时序问题：没开 AFIO、没做 `GPIO_Remap1_CAN1` | 见知识库整理稿 §3.2 |
| 8 | 单节点正常模式发送卡住 | 没有第二节点拉 ACK + `NART=DISABLE` 无限重传 | 至少两节点；调试时用回环/静默；加超时 |

## 12. 和本机 FDCAN 工程的对照

本机 H743 双板与 G0B1 工程用的是 **FDCAN**（新 IP），位时序概念完全一样，只是多了「数据段独立时序」：

| 经典 CAN（本章，bxCAN） | FDCAN（H743/G0B1 工程，HAL） |
|---|---|---|
| `CAN_Prescaler` | `Init.NominalPrescaler`（仲裁段）/ `Init.DataPrescaler`（数据段） |
| `CAN_BS1` | `Init.NominalTimeSeg1` / `Init.DataTimeSeg1` |
| `CAN_BS2` | `Init.NominalTimeSeg2` / `Init.DataTimeSeg2` |
| `CAN_SJW` | `Init.NominalSyncJumpWidth` / `Init.DataSyncJumpWidth` |
| 一套时序跑全帧 | 仲裁段慢速保兼容，数据段可加速（CAN FD 的核心卖点） |

> 一句话：**位时序的概念（SS/传播/相位缓冲/采样点/SJW）在 FD 里原样保留**，学完本章再去配 FDCAN 的 `NominalTimeSeg1/2`，只是把同一套公式算两遍。
